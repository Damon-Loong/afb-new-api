# 模型定价换算说明

## 背景

平台按人民币向用户收费，但上游模型账号的额度以美元计价。

当前示例：

- 账号成本：2300 元人民币
- 账号内额度：约 4400 美金额度
- 上游模型标价：
  - 输入：5 美元 / 1M tokens
  - 补全：25 美元 / 1M tokens
  - 缓存创建：6.25 美元 / 1M tokens
  - 缓存读取：0.5 美元 / 1M tokens

## 实际成本换算

你的真实成本不是按美元汇率计算，而是按账号购买成本计算：

```text
每 1 美金额度的人民币成本 = 2300 / 4400 = 0.5227 元
```

因此该模型的真实人民币成本约为：

| 项目 | 上游标价 | 真实成本 |
| --- | ---: | ---: |
| 输入 | 5 美元 / 1M | 2.61 元 / 1M |
| 补全 | 25 美元 / 1M | 13.07 元 / 1M |
| 缓存创建 | 6.25 美元 / 1M | 3.27 元 / 1M |
| 缓存读取 | 0.5 美元 / 1M | 0.26 元 / 1M |

## 后台填写口径

在后台模型价格编辑页面中，字段是按价格填写，不是按倍率填写。

也就是说，上游写的是：

```text
缓存读取价格 0.5 / 1M
```

后台页面就可以直接填：

```text
缓存读取价格：0.5
```

保存时系统会自动换算成后端计费需要的倍率：

```text
补全倍率 = 补全价格 / 输入价格
缓存读取倍率 = 缓存读取价格 / 输入价格
缓存创建倍率 = 缓存创建价格 / 输入价格
```

例如后台填写：

```text
输入价格：10
补全价格：50
缓存读取价格：0.5
缓存创建价格：2
```

保存后会换算为：

```text
model_ratio = 20
completion_ratio = 5
cache_ratio = 0.05
create_cache_ratio = 0.2
```

用户不需要手动填写这些倍率。

## 不亏本价格

理论保本价约为：

```text
输入价格：2.61
补全价格：13.07
缓存创建价格：3.27
缓存读取价格：0.26
```

但这只是裸成本，没有包含：

- 支付手续费
- 账号风险
- 额度损耗
- 退款和坏账
- 没用完额度的浪费
- 平台运营成本

因此实际售价不建议贴着保本价设置。

## 推荐定价

### 保守不亏

适合先测试市场，价格低但仍有安全垫。

```text
输入价格：3
补全价格：15
缓存创建价格：4
缓存读取价格：0.3
```

### 比较稳的盈利定价

适合长期售卖，有较舒服的利润空间。

```text
输入价格：4
补全价格：20
缓存创建价格：5
缓存读取价格：0.5
```

### 高利润定价

适合模型稀缺、效果好、用户愿意为质量付费的情况。

```text
输入价格：5
补全价格：25
缓存创建价格：6.25
缓存读取价格：0.6
```

## 建议

如果不确定用户接受度，建议先使用“比较稳的盈利定价”：

```text
输入价格：4
补全价格：20
缓存创建价格：5
缓存读取价格：0.5
```

观察一段时间后，根据实际消耗结构调整：

- 如果补全 token 占比高，重点关注补全价格利润。
- 如果缓存读取很多，缓存读取价格不能设置太低。
- 如果用户大量使用长上下文并频繁创建缓存，缓存创建价格要保留足够空间。
